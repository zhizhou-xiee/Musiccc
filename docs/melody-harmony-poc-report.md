# 《借月》旋律与和声 PoC 0.1 报告

日期：2026-10-15

## 结论

WAV 母带足以生成可供人工校对的逐句旋律候选，并且“相对旋律轮廓 + 重复关系”已经表现出补充现有声学曲线的价值。调性可作为少量候选呈现；自动和弦目前不够稳定，不能直接进入 MCP。

本轮只建立研究数据和本地校对工具，未修改线上 MCP、未上传母带或分轨、未产生新的模型 API 费用。

## 母带核对

- WAV：48 kHz、24-bit PCM、双声道，249.734 秒，约 71.9 MB。
- MP3：44.1 kHz、320 kbps、双声道。
- 解码后全曲波形相关约 0.998。
- MP3 相对 WAV 存在固定约 27.25 ms 的编解码延迟；在 5、40、80、120、160、200 秒处均未观察到漂移。

因此二者是同一内容版本，没有剪辑偏移。正式分析改用 WAV；现有歌词时间轴无需整体平移，因为它本来就是按终版音轨人工标记，而 27 ms 远小于当前歌词结束时间的估算误差。

## 方法

1. 使用 Demucs `htdemucs` 将 WAV 二分为人声与伴奏。
2. 在分离人声上以 pYIN（C2–C6，概率阈值 0.60）提取候选基频。
3. 每句压缩成 16 个时间格；无可靠音高的格保留空值，不跨休止强连曲线。
4. 对两遍副歌的对应歌词做时长归一化，比较相对中位音的轮廓相关。
5. 使用全曲谐波色度与 Krumhansl 模板产生调性候选。
6. 在伴奏上跟踪拍点，并对每四个跟踪拍的平均色度匹配 24 个大小三和弦模板。

## 实测结果

### 逐句旋律

- 72 / 72 句生成候选。
- 有效音高覆盖率：最低 27.5%，中位 61.2%，最高 86.0%。
- 自动候选音域总体落在 A2–B4 附近；逐句输出仍可能包含八度错误、和声串入或伴奏残留。

覆盖率不是准确率。特别是 Final Chorus 的多人声、短句和厚伴奏区，低覆盖是预期现象，应优先人工复核。

### 重复副歌

两遍副歌的 11 对对应歌词中：

- 7 对相对轮廓相关系数 ≥ 0.80；
- 3 对位于 0.60–0.80；
- 1 对明显失败：`line-024` / `line-049`“不问阴晴”，相关 0.143。

这说明模型可以可靠地发现大部分“这一句回来了”的关系，但不能将单次低分直接解释成作曲发生变化；它也可能只是分轨或基频跟踪失败。

### 调性、速度与拍号

调性前四候选：

1. D major：0.8094
2. B minor：0.7276
3. F# minor：0.6857
4. A major：0.5652

D 大调是明显的第一候选，B 小调是合理的相对调替代解释。两者都保持自动未校对状态。

伴奏拍点跟踪得到聚合速度 92.285 BPM、中位拍间隔换算 93.963 BPM；旧资料中的约 95.7 BPM 也是自动值。差异表明速度不能在没有工程数据或人工核拍时定稿。拍号继续保持 `unknown`。

### 和弦

84 个四拍窗口中，只有 24 个窗口的第一、第二三和弦模板差距达到 0.08。其余 60 个窗口强制留空。较清晰片段出现 D、G、Bm、F#m、A 等候选，与 D 大调候选相容，但当前方法无法可靠处理：

- 非三和弦与转位；
- 延伸音、经过音和持续音；
- 人声 / 伴奏分离残留；
- 拍点偏移；
- 和声变化快于或慢于固定四拍窗口。

因此和弦只适合作为校对提示，不适合直接提供给模型。

## 面向小机的建议格式

人工校对后，优先保留：

- 旋律相对走向与休止；
- 句内局部峰谷；
- 重复、变奏、移高 / 移低等跨句关系；
- 经确认的调性或局部调性；
- 经确认的少量和声转折。

不要把 16 个候选点原样每轮重复发送。更合理的是将稳定旋律层作为可缓存静态前缀，再由 `music_next` 只揭示当前句的轮廓与已经发生的关系。原始 MIDI 候选和置信度留在证据层，不直接冒充可演奏乐谱。

## 下一道门槛

在进入 MSS / MCP 前至少完成：

1. 用本地校对台试听高覆盖、低覆盖、多人合唱和重复副歌样本。
2. 确认相对走向是否比精确音名更稳定。
3. 人工确认 D 大调 / B 小调解释与真实工程信息。
4. 若无工程和弦表，随机抽查自动和弦候选；准确度不足则整层删除。
5. 设计同 token 预算对照：现有曲线 vs. 曲线 + 已校对旋律关系，并检查事实题增益与主观解释空间。

## 第一轮人工抽听返工

负责人试听候选后报告：整体未发现普遍性大问题，但点名了五处局部现象。本轮将这些现象作为有来源的人工观察保存，而没有把它们扩大解释为完整音高校验。

- `line-001`“水涟涟……”末字“檐”缺失：原候选窗在 11.080 秒结束，稳定单人尾音实际延续到约 12.4 秒。旋律分析窗已延至 12.450 秒；正式歌词时间未擅自改动。
- `line-065`“共此刻”需要返工：改用 24 格与较低概率门槛重新生成，仍保持需修正状态。
- `line-066`“共聚散共未歇”的“未歇”缺失，以及 `line-070`“又翻过窗前”似乎跑调：两句均由两位主唱共同演唱。单基频曲线不能表示双声部，现明确标为 `unsupported_polyphonic_unresolved`，不再开放连续单旋律试听。
- `line-069`“慢慢相见”两个“慢”似乎合并：更细的 24 格显示两个不同平台，中间保留空隙；连续哼唱也按休止分组，不再由每个采样点重新起音。
- 两次“不问阴晴”听感没有明显问题：保留自动相关 0.143 作为失败案例，同时附上人工抽听结论，禁止将低分解释为旋律不同。
- `line-012`“不知路途遥远几许”原先包含了下一句的“直至”：负责人复听母带后确认 68.651–69.190 已是 `line-013`“直至清辉”的前两个字。统一时间轴现以 68.651 秒作为上一句结束和下一句开口，并在 MCP 中分别标成已验证的结束 / 开口。先前关于“只是播放器停止延迟”的诊断被后续人工证据推翻并更正。
- `line-015`“月色无声”的“月”很短、很轻：分离人声能量约在 74.620 秒起升，原参考开口 74.650 秒可能损失少量起音。校对试听窗暂从 74.600 秒开始，局部门槛降至 0.20 并使用 24 格；正式歌词开口仍保留 74.650 秒，等待负责人精确定点。

这轮返工进一步说明：多人声不是“把单旋律算法调准一点”就能解决的问题。第一版给小机的旋律层应只纳入人工确认的单人相对轮廓；双人和四人片段保持多声部未知，除非未来引入可靠的多音高转录或独立声部分轨。
