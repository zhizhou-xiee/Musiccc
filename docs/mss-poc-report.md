# Music Semantic Score (MSS) PoC v0.1 首轮报告

## 结论

《借月》已经能够从统一时间轴、项目负责人精细听音记录和缓存声学测量生成可解析的 `MSS/0.1`。完整输出含 12 个音乐段落、33 个听音事件、4 条段落/事件关系；JSON 已通过 Draft 2020-12 Schema 校验。

MSS 值得进入真实模型对照测试，但本轮**不能证明 MSS 比同预算自然语言摘要理解得更好**。在使用同一批证据并控制约 800 Token 后，两者都显式覆盖 15/15 个事实题，大小也几乎一致。MSS 当前已显示的优势是机器可解析、时间定位稳定、不确定性与来源容易保留，以及适合把静态底谱和播放事件分离；这些优势是否会提高模型答题准确率，仍需真实模型实验。

## 数据修正

2026-10-15 的精细听音记录修正了旧粗标的两处问题：

1. 约 53.285 秒为古筝短暂和声；最早明确记录的轻架子鼓鼓点是约 64.100 秒，不是旧粗表的约 54 秒。
2. 间奏 119.138 秒后的高音乐器不能确定为古筝，应保留“古筝或琵琶”候选。
3. Bridge 的 195.413 秒只记录古筝短暂和声；另一次短暂扬起位于 199.360–200.450 秒的两句歌词衔接窗口，精确落点待试听收窄。

旧摘要因此出现 2 条与新细标冲突的结论，不能再作为正式数据。PoC 将旧版本保留为失败案例，不覆盖来源记录。

## 表示与预算

本机未安装 GPT、Claude、Gemini 的供应商 tokenizer。本轮继续使用 UTF-8 字节数除以 4 至除以 3 的透明代理区间；这不是实际计费 Token。

| 变体 | 目标 | Token 代理 | 显式覆盖（15 题） | 用途 |
|---|---:|---:|---:|---|
| 旧摘要 | 未设 | 706–941 | 2 完整 / 5 部分 / 6 不支持 / 2 冲突 | 过期基线与失败案例 |
| 同证据自然语言 | 800 | 609–811 | 15 完整 | 公平摘要基线 |
| MSS 极简档 | 300 | 217–289 | 8 完整 / 1 部分 / 6 不支持 | 快速概览，不足以完整问答 |
| MSS 标准档 | 800 | 600–800 | 15 完整 | 下一轮重点候选 |
| MSS 细节档 | 1500 | 1157–1543 | 15 完整 | 人工检查与诊断 |

300 档成功守住预算，但丢失演唱者映射、部分段内事件和精确声学比较。1500 档没有在当前 15 题中增加覆盖，只增加可读说明，因此不应在未发现新增理解收益前作为默认注入。800 档是下一轮最合理的比较点。

## 公平性说明

最初一次生成曾得到“旧摘要 2/15、MSS 15/15”的结果，但两者使用了不同精度的证据：旧摘要只看到旧粗标，MSS 看到了新的精细听音记录。该比较已废弃。

正式对照新增 `natural_800.txt`，它与 `mss_800.txt` 使用完全相同的精细听音、演唱者和自动声学证据，并落在同一 Token 代理预算。此时二者的显式信息覆盖打平。下一轮必须比较真实模型能否准确读取时间、关系、不确定性与来源，而不是继续比较输入里有没有答案。

## MSS/0.1 当前能力

- 用毫秒记录乐器进入、退出、前景交接、音区、演奏动作和织体扩展。
- 使用稳定段落 ID 与演唱者 ID。
- 自动响度和频谱指标标记为 `automatic_unverified`。
- 乐器家族级判断与候选判断显式带 `?` 或置信状态。
- 调性、拍号和旋律动机没有可靠依据时保持 `unknown`。
- 可以把静态 `mss_800` 与轻量播放事件分离，例如：

```text
PLAY @119138 | SECTION=it | EVENT=foreground_handoff | fl->(gz|pp)?
```

## 尚未完成

1. 没有真实 GPT、Claude、Gemini 答题结果。
2. 没有供应商 tokenizer 的实际 Token 计数。
3. 没有简化 MIDI 对照；当前缺少可靠且人工核验的主旋律转录。
4. 没有调性、拍号、和弦或旋律动机的可靠识别结果。
5. 只有《借月》一首歌；尚不能证明 Schema 可泛化。

## 下一轮建议

在产生任何模型 API 费用前，先由项目负责人检查 33 个 MSS 事件是否忠实反映听音记录。通过后，使用 `natural_800` 与 `mss_800` 做盲测：同一模型、同一组问题、随机输入顺序，记录事实准确率、时间误差、不确定性保留、幻觉率、实际 Token 与响应耗时。

如果 MSS 只提高可解析性、没有提高模型理解，应把 MSS 留作服务器内部数据层，继续向模型输出自然语言摘要。如果 MSS 在关系推理、时间定位或幻觉率上有明确优势，再考虑将 800 档作为 MCP 的稳定底谱。
